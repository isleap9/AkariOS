<objective>
Let the user take the log with them.

After an install that removes Defender, UAC, VBS and a driver stack, the log is often
the only evidence that exists — and today it is trapped at
`C:\ProgramData\AkariOS\install.log` on a machine that no longer has normal
functionality. DIAG-03 asks the user to be able to export it, with system info, to a
location they choose. Neither exists.

Purpose: make the install diagnosable by someone who is not sitting at the machine.
Output: a system-info collector that never throws, a read-only exporter that writes a
complete copy, a destination picker behind a seam, and a UI card that reports exactly
what was written and where.
</objective>

**T-03-27 — `Get-AkariOSSystemInfo -SystemInfoReader <scriptblock>`.** Create
`AkariOS/functions/public/Export.ps1`. Returns an ordered collection of
`{ Label, Value }` pairs covering: OS caption + version + build + architecture,
PowerShell version, whether the process is elevated, manufacturer / model / serial
(from `Win32_ComputerSystem` / `Win32_Bios`), total and free physical memory, disk free
space on the system drive, the AkariOS state (`Status`, `CurrentStage`), the log path,
and the machine uptime.

The `-SystemInfoReader` default does the real `Get-CimInstance` work, but EVERY field is
individually wrapped: a probe that fails or returns nothing yields `"unavailable"`, never
an exception. Follow `Test-PowerState`'s precedent — `Win32_Battery` being absent on a
desktop is not an error, and neither is `Win32_DiskDrive` on a Server SKU. Assert this
property in the harness by running the REAL default reader with an injected stub that
throws for every class.

SECURITY GATE ON CONTENT: the collected set must contain no secret material. No product
keys (`HKLM\...\DigitalProductId` is out), no machine-account passwords, no `Win32_UserAccount`
`Password` field, no user profile paths (`Win32_UserProfile`), no network credentials, no
`ipconfig` output, no `Get-ChildItem` of the user's home. Firmware serial is
borderline — include it but label it clearly, because it is what makes a support
conversation possible, and exclude anything that could authenticate as the machine. The
harness asserts on the LABELS and the field list: no label matching
`password|secret|productkey|credential|profile path`, and the reader scriptblock is
asserted on comment-stripped source to contain no `DigitalProductId`, no
`Get-Credential`, no `HKLM:\...\Password`, no `$env:` expansion of a secret-shaped name.

**T-03-28 — `Export-AkariOSLog -DestinationPath -LogPath -SystemInfoReader
[-FileWriter <scriptblock>]`.** Writes
`<DestinationPath>\AkariOS-log-<yyyyMMdd-HHmmss>.txt` containing, in order: an
AkariOS export banner with the export timestamp, the system-information block from
T-03-27, a separator, then the ENTIRE live log verbatim.

D-23, READ-ONLY: this function never writes to `-LogPath`, never moves it, never calls
`Initialize-AkariOSLog` (which rotates and writes a banner — calling it here would
mutate the very log being exported), never deletes it. The harness asserts the log
file's bytes are byte-identical before and after the export, and that no rotated
`install.log.1` appeared.

The default `-FileWriter` is `[System.IO.File]::WriteAllText($path, $text, (New-Object
System.Text.UTF8Encoding($false)))` — the same BOM-free writer `Expand-AkariOSEngineAsset`
and `Set-AkariOSState` already use. Write to a temporary name in the destination
directory and move it into place, so an interrupted export never leaves a half-written
file that looks complete.

Handle a MISSING log (`Test-Path` false): still produce an export containing the system
information plus an explicit line stating the log was not found at that path, and set a
`LogIncluded = $false` flag on the return object. Do NOT throw — an export that fails
because the log is absent is useless exactly when it is most needed.

Return `{ Path, Bytes, LogIncluded, LineCount, CreatedAt }`.

**T-03-29 — Destination validation, before any write.** Reject, with a specific reason
and NO file created: a destination that does not exist; a destination that is a file
rather than a directory; a name whose combined length exceeds the path limit; a
destination the process cannot write to (probe by attempting the temp-file write, not by
inspecting ACLs). Do NOT silently overwrite: because the filename carries a timestamp,
a collision means two exports in the same second, so append a `-2`, `-3` suffix rather
than clobbering. Return `$false` with a reason; never throw to the caller.

## Threat Model

### Trust Boundaries

| Boundary | Description |
|----------|-------------|
| System probes -> exported file | `Get-CimInstance` output from a possibly-compromised machine is written to a file the user will share with someone else |
| User-chosen folder -> file write | The destination is arbitrary; a wrong or hostile path writes somewhere unexpected, or over something |
| Log content -> exported file | `install.log` contains registry paths, service names and error text from a partially-failed system; it is machine detail but not credential material |
| Exported file -> third party | The user is explicitly going to send this to someone. Its contents become the tool's disclosure surface |
