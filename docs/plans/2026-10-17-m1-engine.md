# M1: Engine Implementation Plan

**Goal:** Pull the engine out of `Akari.ps1` into `Core/`, so one-file tweaks load, apply, revert and report State from a CLI (`-List`, `-Apply`, `-Revert`), while the GUI keeps running every existing tweak through an `Add-Tweak` adapter.

**Architecture:** `Core/*.ps1` are dot-sourced function files (no modules): Log, Compat, Trusted, Registry, Loader, State, Runner, Legacy. The Loader reads `Tweaks/<Section>/<Category>/*.ps1` hashtable files into normalized tweak objects. The Legacy adapter loads the 8 old `Tweaks/*.ps1` files into the same shape. The Runner applies or reverts a tweak and returns an Outcome. The GUI's background runspace dot-sources the same Core files instead of the `$Helpers` here-string.

**Tech Stack:** Windows PowerShell 5.1, WPF (unchanged), Pester 3.4.0 (ships with Windows, `C:\Program Files\WindowsPowerShell\Modules\Pester\3.4.0`).

**Spec:** `AkariOS-PLAN.md` §4 (Modes, Run summary), §5 / §5.1, §6, §7, §12 (M1 row); `GLOSSARY.md`; `docs/adr/0001-revert-to-windows-default.md`.

## Global Constraints

- PowerShell 5.1 only: no `??`, `?:`, `?.`, `&&`, `-AsHashtable`, `ForEach-Object -Parallel`.
- Glossary terms in code and messages: Apply / Revert (not optimize/undo), Outcome values exactly `Applied`, `Reverted`, `Already`, `Skipped`, `Failed`; State values exactly `Optimized`, `Default`, `Custom`, `Unknown`.
- Risk ∈ `Safe`, `Caution`, `Advanced`. Kind ∈ `Toggle` (default), `Choice`, `Action` (`Group` is rejected in new-format files until a later milestone).
- Tweak ids: kebab-case, regex `^[a-z0-9]+(-[a-z0-9]+)*$`, unique.
- No tweak logic in `Core/` (AGENTS.md rule 3). HKCU writes go to the real logged-in user's hive (rule 6).
- Tweak script blocks must not contain `Pause`, `Read-Host` or `Clear-Host` (rule 7).
- Log file stays `%LOCALAPPDATA%\Akari\akari.log`; remembered state stays `%LOCALAPPDATA%\Akari\state.json`.
- Tests write only under `HKCU:\Software\AkariTest\<guid>` and Pester's `TestDrive:`, and clean up after themselves.
- Run tests with `powershell -NoProfile -ExecutionPolicy Bypass -File Tests\Run.ps1` (non-elevated is fine).

**Out of scope for M1** (later milestones): restore point, `Requires` checks (field is accepted, not enforced), Groups/Entries in new-format files, Choice values on the CLI (`id=value`), Presets, Phases, Choice combobox, `Build/Bundle.ps1`.

## Review Focus

1. **Elevated as a different admin account (UAC with other credentials):** a Registry entry under `HKCU:` must land in the logged-in user's `HKEY_USERS\<sid>`, not the elevated account's. Test: Task 2, `Resolve-AkariRegPath` with `$script:AkariUserSid` set.
2. **`-List` from a non-elevated shell:** a `Detect` that throws (e.g. `Get-MMAgent` without admin) must show State `Unknown`, not crash the listing. Test: Task 4, "Detect that throws is Unknown".
3. **`Write-Host` shim in the CLI:** with `Core/Compat.ps1` loaded and no `$LogQueue`, `Write-Host 'x'` must print once, not recurse through `Write-Log`. Test: Task 1.
4. **One broken tweak file** (syntax error, missing field) must not stop the others from loading; it shows up as a Problem naming the file. Test: Task 3.
5. **Unknown or failing id in a Run:** the remaining ids still run, the bad one is `Failed`, and the CLI exits 1. Test: Task 5 (`Invoke-AkariRun`) and Task 6 (CLI exit code).

### Task 2: Core/Registry.ps1

**Files:**
- Create: `Core/Registry.ps1`, `Tests/Registry.Tests.ps1`

**Interfaces:**
- Consumes: nothing.
- Produces:
  - `Get-AkariUserSid() -> string`: returns `$script:AkariUserSid` if set. Otherwise it caches and returns the SID of the owner of `explorer.exe` in the current process's session (`Get-CimInstance Win32_Process -Filter "Name='explorer.exe' AND SessionId=<pid session>"` → `Invoke-CimMethod GetOwnerSid`). Falls back to `[Security.Principal.WindowsIdentity]::GetCurrent().User.Value`.
  - `Resolve-AkariRegPath([string]$Path) -> string`: `HKCU:\X` or `HKEY_CURRENT_USER\X` → `Registry::HKEY_USERS\<sid>\X`; anything else unchanged.
  - `Resolve-AkariDefault($Default) -> object`: a hashtable with `Win10`/`Win11` keys → the value for this OS (`[Environment]::OSVersion.Version.Build -ge 22000` → Win11); anything else returned as is.
  - `Get-AkariRegValue([string]$Path, [string]$Name) -> object`: `$null` when the key or value is absent. DWord read as negative Int32 is returned as the unsigned value (`[BitConverter]::ToUInt32([BitConverter]::GetBytes([int]$v), 0)`).
  - `Set-Reg($Path, $Name, $Value, $Type = 'DWord')`: same signature as today. Resolves the path and creates the key. A DWord value above `[int]::MaxValue` is written as its signed Int32 equivalent.
  - `Remove-Reg($Path, $Name)`: resolves the path and removes it silently if absent.
  - `Invoke-AkariRegistry([hashtable[]]$Entries, [ValidateSet('Apply','Revert')]$Mode)`: Apply → `Set-Reg` each entry's `Value`. Revert → `Resolve-AkariDefault` each entry's `Default`; `$null` → `Remove-Reg`, else `Set-Reg`.
  - `Get-AkariRegistryState([hashtable[]]$Entries) -> string`: `Optimized` if every entry's current value equals `Value`. `Default` if every entry equals its resolved Default (absent counts as equal when that Default is `$null`). `Custom` otherwise. `Unknown` if a read throws. Compare with `-eq` after casting the current value to the expected value's type.

### Task 3: Core/Loader.ps1

**Files:**
- Create: `Core/Loader.ps1`, `Tests/Loader.Tests.ps1`, fixtures under `Tests/Fixtures/Tweaks/<Section>/<Category>/*.ps1`

**Interfaces:**
- Consumes: none.
- Produces:
  - Normalized tweak object (`[pscustomobject]`) with exactly these properties: `Id, Name, Description, Section, Category, Kind, Risk, Button, Confirm, Reboot, SafeMode, Requires, Registry, Choices, Recommended, Default, Editable, Apply, Revert, Detect, Check, Actions, Source, Legacy`. Defaults: `Kind='Toggle'`, `Button='Run'`, `Reboot=$false`, `SafeMode=$false`, `Editable=$false`, `Legacy=$false`. `Registry` is always `[hashtable[]]` or `$null` (a single hashtable is wrapped). `Source` is the file's full path.
  - `Import-AkariTweakFile([string]$Path, [string]$TweaksRoot) -> tweak`: runs `& $Path`. Throws `"<relative path>: <reason>"` on the first rule broken.
  - `Get-AkariTweaks([string]$TweaksRoot) -> @{ Tweaks = List[object]; Problems = List[object] }`: scans `*.ps1` exactly two folders below `$TweaksRoot` (`<Section>\<Category>\file.ps1`, so the legacy top-level files are ignored). Each Problem is `[pscustomobject]@{ File; Level = 'Error'|'Warning'; Message }`. A file that throws becomes an Error and is skipped. A duplicate `Id` is an Error on the second file.
- Rules checked in `Import-AkariTweakFile`, in this order (each one is an Error unless marked Warning):
  1. The file returns a hashtable.
  2. `Id`, `Name`, `Description`, `Section`, `Category`, `Risk` are present; `Id` matches the kebab regex; `Risk` and `Kind` are in their sets; `Kind='Group'` → "Groups are not supported in tweak files yet".
  3. The parent folder name equals `Category` and the grandparent equals `Section`.
  4. Toggle: `Registry`, or both `Apply` and `Revert`. Each Registry entry has `Path`, `Name`, `Type`, `Value`, and a `Default` key (`ContainsKey`, so `$null` is allowed).
  5. Choice: one Registry entry with `Path`, `Name`, `Type`; `Choices` non-empty; `Recommended` and `Default` keys present; `Recommended` is one of the Choices' `Value`s unless `Editable`.
  6. Action: `Apply` present; the file text has a line matching `^\s*#\s*Action:\s*\S` (the one-line reason it can't be a Toggle).
  7. No script block (`Apply`, `Revert`, `Detect`, `Check`) text matches `(?i)\b(Pause|Read-Host|Clear-Host)\b`.
  8. Warning (via `Get-AkariTweaks`, not a throw): a Toggle with no `Detect` and no `Registry` → "no Detect: State falls back to what Akari last applied".

### Task 5: Core/Runner.ps1

**Files:**
- Create: `Core/Runner.ps1`, `Tests/Runner.Tests.ps1`

**Interfaces:**
- Consumes: Tasks 1–4.
- Produces:
  - `Invoke-AkariTweak($Tweak, [ValidateSet('Apply','Revert')]$Mode) -> [pscustomobject]@{ Id; Mode; Outcome; Reboot; Message }`:

It runs a preamble that dot-sources `Log, Compat, Trusted, Registry, Loader, State, Runner` from `$CoreDir`, then runs `$Code` with the same `*>&1 | Out-String -Stream | Write-Log` and `catch { Write-Log ('Error: ' + ...) }` wrapping as `Akari.ps1:613`.
