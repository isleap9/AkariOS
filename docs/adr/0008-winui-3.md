# AkariOS looks and moves like a WinUI 3 app, with Akari crimson as its accent

Decided 2026-11-19 (plan `docs/plans/2026-11-19-winui-3.md`; reference `docs/design/akarios-prototype.html`).
Supersedes ADR 0006's identity: the warm themes, the lamp glows, Unbounded / Manrope / JetBrains Mono, Lucide line
icons, pill controls, top tabs and the hero go. Keeps ADR 0006's theme mechanism: two brush dictionaries
(`Theme.Dark.xaml`, `Theme.Light.xaml`) swapped at runtime by `Set-AkariTheme`, every brush named through
`DynamicResource` / `SetResourceReference`, no colour literal outside the theme files.

AkariOS becomes a Windows 11 app: WinUI 3's colours, type ramp (Segoe UI Variable), control metrics, a left
NavigationView with a Settings page, settings cards, expanders, InfoBars, ContentDialogs and toasts, Fluent System
Icons, and Fluent's motion (83 / 167 / 250 / 333 ms, the decelerate curve cubic-bezier(0,0,0,1) for entrances and
cubic-bezier(.55,.55,0,1) for exits). **Akari crimson stays as the accent** (`Acc` #FF6B7D dark, #C8102E light), and
appears only where Windows would put its accent; Settings › Accent colour can follow the Windows accent instead.

The crimson identity made AkariOS recognisable, but beside the Windows settings it changes it read as a themed web
page, and crimson on everything made routine choices look alarming. A Windows optimizer that gamers use should look
like the Settings app it sits next to; keeping crimson as the accent keeps the brand where it belongs. The prototype is
the reference: where the plan and the prototype disagree, the prototype wins; where neither says, Windows 11 Settings
does.

## Considered Options

- **Keep the identity, soften it**: rejected; the fonts, pills and top tabs still read as a web page.
- **The user's Windows accent only** (ADR 0008 of 2026-11-17, reverted): rejected; a blue AkariOS loses the brand.
  It stays as an option.
- **WinUI 3 / Windows App SDK**: rejected; the PowerShell app can only use WPF and both apps share one set of XAML.
  The look and motion are rebuilt in WPF from WinUI's values.

## Consequences

- The accent is crimson by default; `Set-AkariAccent` puts `Acc AccH AccP AccT AccText AccSoft Info` into the current
  theme dictionary when Settings says "Windows accent" (read from the real user's `Explorer\Accent\AccentPalette`,
  rule 6), again on `WM_SETTINGCHANGE` and `WM_DWMCOLORIZATIONCOLORCHANGED`. The choice is `Accent` in
  `settings.json`, next to `Theme`.
- No glows: `Glow`, `AccC` and every accent `DropShadowEffect` go. The only light effect is the Home hero's `AccSoft`
  radial; shadows stay on tooltips, flyouts, dialogs, toasts and tiles on hover.
- Fonts are Windows' own (Segoe UI Variable, Segoe UI on Windows 10; Cascadia Mono, Consolas) and icons Microsoft's
  (Fluent System Icons, MIT): nothing ships under the OFL.
- Easing is a `KeySpline` (`0,0 0,1` in, `0.55,0.55 0,1` out) on a spline key frame, exact to WinUI's curves.
  Animations are off (every duration 0) when Windows' animation effects are off, with `AKARI_MOTION=off`, or with
  Settings › Animation effects off.
- Animations stay on Opacity and transforms, with **three exceptions**, the only layout properties animated, because
  WPF has no transform that reflows the content under them:
  1. the navigation pane's **width** (280 ↔ 48 px, `Motion.Slow`);
  2. an expander's body **height** (0 ↔ its measured height, `Motion.Base`, the chevron turning 180°);
  3. an InfoBar's **height** (with its opacity, `Motion.Slow`).
  Each measures the target, animates a fixed value, then hands the property back (`Auto` / `NaN`).
- The nav indicator's stretch (a 3 × 16 px bar that grows to cover both items halfway, then shrinks onto the new one,
  300 ms) is a `ScaleTransform` on Y with a `TranslateTransform`, not a height animation.
