# AkariOS: agent guide

PowerShell 5.1 + WPF app that debloats and optimizes Windows 10 22H2 / 11 for gaming. `src/Akari.ps1` is the entry point (GUI and CLI, presets).

- Vocabulary: [`docs/GLOSSARY.md`](docs/GLOSSARY.md). Use its terms in code, comments and docs (Tweak, Toggle, Choice, Action, Group, Entry, Apply, Revert, Default, State, Preset, Run, Outcome).
- Plan and target architecture: [`docs/PLAN.md`](docs/PLAN.md). Decisions: [`docs/adr/`](docs/adr/).
- Repo root: `README.md`, `LICENSE`, `CREDITS.md`, this file; `src/` = what Akari runs from and the release zip ships (every path below without a folder is under `src/`: `Akari.ps1`, `Core/`, `UI/`, `Tweaks/`, `Presets/`, `OneClick/`, `Assets/`); `tests/` (Pester; fixtures in `tests/Fixtures/`); `build/` (`Bootstrap.ps1`, `Launcher.cs` + `Launcher.manifest` = `AkariOS.exe`, `Icons.ps1` = `src/UI/Icons.xaml`, dev-only); `docs/`; `.github/`; `graphify-out/` (the graphify knowledge graph, kept in the repo).

## Current layout (transitional)

The port is in progress (M1 Engine, M2a Manual steps, M3 Windows port + Presets and M4 One-click, M5 Import / Export done; plans in `docs/plans/`).

- `Akari.ps1`: `-Resume` branch (a Run in phases goes on after a restart: RunOnce, console only, `Get-AkariRun` → `Start-AkariPhases`, summary at the end), CLI branch (`-List`, `-Apply id,id`, `-Revert id,id`, `-Preset <name|file.json>`, `-RevertPreset <name|file.json>`; all but `-List` need an elevated shell; preset wildcards read what is on the PC; a preset Run goes through `Start-AkariPhases`, so a preset with Phases restarts between them), then elevation (the elevated console stays visible: launch banner, live log), Core and tweak loading, and dot-sourcing `UI/*.ps1`; after the window closes for One-click, the AkariOS preset's Run in the console (`New-AkariPresetRun`, `Start-AkariPhases`).
- `Core/` (dot-sourced function files, no tweak logic):
  - `Log.ps1`: `Write-AkariBanner` (the console banner: the logo in `Assets/ascii.txt` through `Get-AkariBannerArt`, dots white, `+` / `=` dark grey; the old text banner if the file is missing), `Write-Log` (GUI queue, printed to Akari's console window, or straight to the console), `Write-ErrLog` (`%LOCALAPPDATA%\Akari\akari.log`), `Write-AkariProblems <problems> <show>` (the loader's Problems: Warnings to akari.log only, Errors through `<show>` too), `Write-AkariCrash <error> [-Wait]` (`Akari.ps1`'s trap, which covers every branch: akari.log, then a message box when WPF is loaded, else the console; `-Wait` for the RunOnce consoles).
  - `Compat.ps1`: no-op / dialog shims for legacy tweak bodies (`Write-Host`, `Pause`, `Read-Host`, file pickers). Loaded only in the GUI job.
  - `Trusted.ps1`: `Run-Trusted`; `Invoke-AkariRegistryTrusted <rows> <Mode>` (HKLM registry rows written as TrustedInstaller, a few per `Run-Trusted` call; for keys an admin can't change, e.g. Defender's).
  - `Registry.ps1` (literal paths everywhere: `HKLM:\SOFTWARE\Classes\*` is the "all files" key, never a wildcard; a key's unnamed value is Name `'(default)'`; a DWord written as a hex literal compares unsigned; an ExpandString row compares with its `%vars%` expanded, as it reads back): `Set-Reg`, `Remove-Reg`, `Get-AkariRegValue`, `ConvertFrom-AkariHex <'ab,01'>` (→ `[byte[]]`: binary values in a data .psd1 are kept as hex text), `Resolve-AkariRegPath` (HKCU → real user's `HKEY_USERS\<sid>`), `Invoke-AkariRegistry`, `Get-AkariRegistryState` (rows: values, `Binary` = `[byte[]]`, or key rows with no `Name`: `Value` / `Default` = `'Key'` (exists, created empty) or `$null` (deleted with its contents), `Test-AkariKeyRow`, `Get-AkariRegKey`), `Get-AkariUserFolder <name>` (the real user's `AppData`, `Local AppData`, `Desktop`, `Programs`, `Downloads`…).
  - `Loader.ps1`: `Get-AkariTweaks <TweaksRoot>` → `@{ Tweaks; Groups; Problems; Ported }`, `Import-AkariTweakFile`, `ConvertTo-AkariTweak`. Rules in plan §7. One owner per registry value: `Find-AkariRegistryOwner` rejects a Tweak setting a value (or something inside a key row) another one-file Tweak already owns. `Requires` must be in `$AkariRequirements`. `Guided = $false`: shown on Optimize › Advanced only (default: Guided too); Section `Tools` (checks, Refresh, drivers, cleanup) is the Catalogue's only. `Get-AkariPorted` reads `Tweaks/Ported.psd1`, `Test-AkariPorted <ported> <all tweaks>` (pure) reports ids that don't exist. Data-list Groups (ADR 0002, `EntryKind` in `$AkariEntryKinds`: `AppxRemove`, `CapabilityRemove`, `FeatureDisable`, `StoreInstall`; each kind = its button, restart flag and Apply / Detect text): Entries `<group-id>/<name>` built by `New-AkariEntry` (named from the data file row, `Get-AkariEntryRow`; `Keep` from the row or the Group's `KeepNames` patterns). `Rows` kinds (AppxRemove, StoreInstall) load every data file row as a Tweak; the other kinds list only what is on the PC, so their Entries exist once the GUI reads them; `Resolve-AkariEntry` builds any Entry from its id (the GUI's job and the CLI use it).
  - `Appx.ps1`: engine side of the Remove tab. `AppxRemove`: `Get-AkariAppxPackages` (the only raw read; tests mock it), `Get-AkariAppxInstalled`, `Test-AkariAppxInstalled`, `Remove-AkariAppx` (all users + provisioned copy; refuses the never-list `$AkariAppxNever`). `CapabilityRemove`: `Get-AkariCapabilitiesInstalled`, `Test-AkariCapabilityInstalled`, `Remove-AkariCapability`. `FeatureDisable`: `Get-AkariFeaturesEnabled`, `Test-AkariFeatureEnabled`, `Disable-AkariFeature`. The DISM cmdlets are only called through these.
  - `Winget.ps1`: engine side of the `Winget` field: `Install-AkariWingetPackage <id> [msstore]`, `Test-AkariWingetInstalled <id> [msstore]`, `Install-AkariMicrosoftStore` (re-registers the Store, else winget msstore product `9WZDNCRFJBMP`, else `wsreset -i`; each step logged; run before any msstore install), `Install-AkariWingetTool` (makes sure winget ≥ 1.6 works: re-registers App Installer, else installs it from Microsoft's winget-cli GitHub release). winget.exe only through `Invoke-AkariWinget`, App Installer only through `Register-` / `Install-AkariAppInstaller`: tests mock those.
  - `AppSetup.ps1`: helpers for app installs, no app logic: `Save-AkariFile <name> <out>` (AkariOS-Files release), `Remove-AkariStartup <names>` (Run values, wildcards), `Remove-AkariUpdaters <name> [<activeSetup>]` (services, tasks, Active Setup), `New-AkariShortcut <name> <target>` (Start menu, all users), `Get-AkariMsi` / `Uninstall-AkariMsi <display name like>` (msiexec), `Invoke-AkariSelfUninstall <exe> <process>` (`/Uninstall` tools such as mstsc, closes their window), `Get-AkariWingetExe <id> <filter>` (the .exe of a portable winget package, for a Start-menu shortcut), `Find-AkariProgram <id> <exe>` (that portable copy, else `<exe>` at most two folders down in Program Files), `Open-AkariWingetTool <id> <exe>` (a Tools check: installs the winget package only when its program is missing, then opens it), `Invoke-AkariRegExe <args>` (reg.exe: load / import / unload; returns the exit code), `Import-AkariRegText <text>` (reg.exe import; HKEY_CURRENT_USER keys go to the real user), `Import-AkariAppSettings <family> <regText>` (a Store app's own settings.dat, the real user's: loaded at `HKLM\AkariAppHive`, the .reg text imported, unloaded; `$false` when it has none or it won't load), `Read-AkariAppSettings <family>` (read only: a copy of that hive loaded at `HKLM\AkariAppRead`, `reg export`ed, parsed by the pure `ConvertFrom-AkariRegExport`; `'Key\Name'` → `[byte[]]`, `@{}` with no settings, `$null` while the app holds the file), `Get-AkariAppSettingState <family> <rows>` (a Detect from the first byte of each value: rows `@{ Name; Value; Default }`; unset = Default; unreadable = Unknown).
  - `State.ps1`: `Get-AkariState` → Optimized / Default / Custom / Unknown; `Get-AkariChoiceValue <tweak>` (a Choice's current value: its registry row, or its `Value` block for a Choice over many settings; every Choice read goes through it); `Get/Set-AkariRememberedState` (`state.json`).
  - `Runner.ps1`: `Invoke-AkariTweak <tweak> <Mode> [<Value>]` (Value: a Choice value other than Recommended; a Choice with a `Value` block runs its Apply with `$AkariValue` = the value, its Revert for the Default), `Invoke-AkariPlan <@{Id;Mode;Value}[]>` and `Invoke-AkariRun <ids> <Mode>` → one Outcome per item (changes that restart the PC run last, after Explorer's restart: `Test-AkariRestarts <tweak> <Mode>` = `Restarts = $true` on Apply (the block restarts the PC itself, e.g. DDU), or the block's text matches `$AkariRestartPattern` (shutdown /r, Restart-Computer, bcdedit safeboot); Review says so through `Get-AkariRestartNote`, UI/Selection.ps1; a registry Toggle's `After` block runs after its rows on Apply and Revert, with `$AkariMode`; unmet `Requires` = Skipped either way; `SafeMode = $true` Tweaks outside Safe Mode are not run now: once the rest is done, a Run (Core\Phases.ps1) restarts into Safe Mode for them and back, their Outcome says so with Reboot; a SafeMode Tweak's `Prepare` block runs first, in normal mode (`Invoke-AkariPrepare`, once per item: a download, Safe Mode has no network; failed = Failed Outcome, left out of Safe Mode; `Start-AkariPhases` does the same for a preset's own Safe Mode Phase); every block runs through `Invoke-AkariTweakBlock`; a Run restarts Explorer once at the end when a Tweak with `Explorer = $true` was Applied or Reverted); `Start-AkariJob <code> <queue> <CoreDir> [<Shared>]` (GUI background runspace with Core loaded; `$AkariShared` hands objects back). Detect / Apply / Revert / Before / After blocks see `$AkariTweakDir` (the tweak file's folder; `Get-AkariState` sets it for Detect too). In those blocks a cmdlet error fails the tweak (`-ErrorAction Stop` by default), but a native tool's stderr (`reg.exe`, `powercfg`) is only logged: never set `$ErrorActionPreference = 'Stop'` around native calls (5.1 aborts on their stderr). A Core wrapper with a `[Parameter(...)]` param is an advanced function and takes that `-ErrorAction Stop` too: it sets `$ErrorActionPreference = 'Continue'` before its native call (`Invoke-AkariRegExe`, `Invoke-AkariPowerCfg`).
  - `Phases.ps1`: Runs in phases across restarts. A Run = `@{ Name; Sid; Next; Phases = @(@{ Name; Boot = Normal|SafeMode; Items }); Outcomes }`, saved to `$AkariRunPath` (`%ProgramData%\Akari\run.json`): `New-AkariRun`, `Save-` / `Get-` / `Clear-AkariRun`, `New-AkariPresetRun <preset> <loaded> [-Revert]` (wildcards read now) → `@{ Run; Tweaks; Unknown }`, `Get-AkariRunTweaks <run> <loaded>` (Entries rebuilt from their ids on resume), `Split-AkariSafeModePhases` (SafeMode Tweaks of a Normal phase get their own Safe Mode phase), `Start-AkariPhases <run> <tweaks>` → Outcomes, then `Done` / `Restarting` / `Stopped` (restarts into a phase's Boot first; sets up the next boot (`Set-AkariNextBoot`: safeboot + RunOnce `*!akari-resume` / `!akari-resume` = `Akari.ps1 -Resume`) before a phase that ends in a restart; a Failed change in Safe Mode stops the Run and turns Safe Mode off; a multi-phase Run ends with a restart when its last phase needs one; uses the saved Sid for HKCU; phase headers, Outcomes, restarts and stops also go to akari.log), `Write-AkariRunSummary`. Plus `Test-AkariSafeMode`, `Register-AkariResume` (HKCU RunOnce, real user), `Get-AkariResumeCommand`, `Set-AkariSafeBoot` (through `Invoke-AkariBcdEdit`, the only bcdedit change; throws only when it can't turn Safe Mode on), `Restart-AkariPC`. Loaded everywhere (GUI, CLI, the job, `-Resume`).
  - `System.ps1`: `Get-AkariOSBuild`, `Get-AkariEdition` (the registry's EditionID; `Core*` = Home), `Get-AkariChassis` (Laptop / Desktop), `Get-AkariGpus` (the display adapters' driver keys: `@{ Path; Name; Vendor }`, Vendor NVIDIA / AMD / Intel / Other; per-GPU tweaks write under Path), `Get-AkariGpuDevices` (their PCI instance ids), `Test-AkariRequirement <tweak>` → `$null` or `'needs <x>'` (Requires: Win10, Win11, Laptop, Desktop, Home, Pro (= Pro or higher), NVIDIA, AMD, Intel); `Restart-AkariFirmware` (shutdown /r /fw, the only firmware restart; returns the exit code), `Restart-AkariExplorer` (stops it; Windows restarts the shell as the user), `Set-AkariDesktopWallpaper <path>` (refreshes the desktop; the tweak writes the registry), `Invoke-AkariCsc <source> <out>` (compiles C# with the .NET Framework compiler), `Invoke-AkariPowerCfg <args>` (the only powercfg call), `Read-AkariBcd [-Id]` (a boot store entry as text, `{current}` unless `-Id` says e.g. `{globalsettings}`; read only; changes go through `Invoke-AkariBcdEdit`), `Invoke-AkariW32tm <args>` (the only w32tm call; starts W32Time first), `Remove-AkariPaths <paths>` (the cleanup Actions' only bulk delete, wildcards allowed; returns the count), `Invoke-AkariWevtutil <args>`, `Invoke-AkariCleanMgr <set>` (cleanmgr /sagerun, closed when frozen), `Get-AkariDriverPackages` (Get-WindowsDriver -Online, read only) and `Remove-AkariDriverPackage <oemNN.inf>` (pnputil /delete-driver, never /force), `Get-` / `Set-AkariHostsBlock <name> [<lines>]` (Akari's named blocks in the hosts file, `$AkariHostsPath`; the user's lines untouched; no lines = the block removed), `Grant-AkariOwnership <path>` (takeown + icacls for the administrators group), `Set-AkariScheduledTask <path> <name> <enabled>`, `Remove-AkariScheduledTasks <keep names>` (unregisters every other task; returns the count), `Invoke-AkariExe <path> <args>` (a tool a tweak runs: 7-Zip, lodctr; returns the exit code). Tests mock these.
  - `Presets.ps1`: presets (plan §8): `Read-AkariPreset`, `Get-AkariPresets <builtinDir>` (built-in `Presets/*.json`, then `$AkariPresetDir` = `%LOCALAPPDATA%\Akari\presets`), `Find-AkariPreset <name|file>`, `Resolve-AkariPreset <preset> <tweaks> [-Revert]` (pure) → `@{ Items; Unknown }` (items carry their `Phase` index), `Get-AkariPresetPhases <preset> <items> [-Revert]` (pure: the Run's phases; one Normal phase for a flat preset or a Revert), `Save-AkariPreset`, `Get-` / `Save-AkariLastUsed` (`$AkariLastUsedPath`); `Save-AkariPreset` takes `$Extra` top-level fields. Export (M5): `Get-AkariExportTweaks` (one-file Toggles / Choices this PC meets, no Apps / OneClick / Tools), `ConvertTo-AkariExportItems` (pure: Optimized Toggles, Choices off their Default), `Get-AkariExportItems` (reads the States), `Export-AkariSettings <tweaks> <path> [<version>]` → `@{ Path; Count }` (a preset named after the PC, with an `Exported` block). The background job loads `Presets.ps1` too. Entries: `"id"` = Apply, `{"id": value}` = a Choice value, `{"id": "Default"}` = Revert, `"<group>/*"` = the Group's non-keep Entries on this PC. A preset has `Tweaks`, or `Phases` = `[{ Name, Boot: Normal|SafeMode, Tweaks }]` (`Entries` then lists them all, each with its `Phase`).

## Rules

1. One tweak per file. If a file passes ~150 lines, split it. Data-list Groups (same-shape Entries) may be one data file (ADR 0002).
2. Every Toggle and Choice has a Revert to the stock Windows Default (ADR 0001). A Tweak is an Action only when no Default exists; the file says why in one line.
3. No tweak logic in `Core/`. Core = helpers, loader, runner only.
4. The GUI never hard-codes tweaks; it builds from the loader output.
5. Open only the tweak file(s) being changed; don't read the whole `Tweaks/` tree or a bundled `Akari.ps1`.
6. HKCU changes must target the real logged-in user hive, not the elevated/SYSTEM one.
7. Tweak script blocks must not be interactive: no `Pause`, `Read-Host`, `Clear-Host`.
8. Credit upstream sources in `CREDITS.md` when porting a tweak.
9. Never copy code from Winhance (PolyForm Shield). Ideas and layout only.
10. Update this file in the same change whenever the layout or a Core API changes.
11. `_ref/` is reference only: read a file there only when the task names it; never scan it whole, never commit or bundle it.
12. Never launch the GUI or run the CLI on the developer's real machine, in tests or by hand. Tests use fixture tweaks, `HKCU:\Software\AkariTest\<guid>` and `TestDrive:`; CLI tests use `-List` or fake ids. The user does all real testing on a VM — never on the developer's machine. System-changing native commands (`bcdedit`, `shutdown`, …) are called only through a PowerShell function (e.g. `Invoke-AkariBcdEdit`) and tests mock that function, asserting the mock was hit: Pester 3 does not reliably mock a native command (a `Mock cmd` let the real `bcdedit` run once).
