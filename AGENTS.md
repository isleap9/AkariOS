# AkariOS: agent guide

PowerShell 5.1 + WPF app that debloats and optimizes Windows 10 22H2 / 11 for gaming. `Akari.ps1` is the entry point (GUI and CLI, later also presets).

- Vocabulary: [`GLOSSARY.md`](GLOSSARY.md). Use its terms in code, comments and docs (Tweak, Toggle, Choice, Action, Group, Entry, Apply, Revert, Default, State, Preset, Run, Outcome).
- Plan and target architecture: [`AkariOS-PLAN.md`](AkariOS-PLAN.md). Decisions: [`docs/adr/`](docs/adr/).

## Current layout (transitional)

The port is in progress (M1 Engine, M2a Manual steps and M3 Windows port + Presets done; plans in `docs/plans/`).

- `Akari.ps1`: `-Resume` branch (a Run in phases goes on after a restart: RunOnce, console only, `Get-AkariRun` → `Start-AkariPhases`, summary at the end), `-OneClick 2|3` branch (the old imported bodies, kept until the M4 VM check), CLI branch (`-List`, `-Apply id,id`, `-Revert id,id`, `-Preset <name|file.json>`, `-RevertPreset <name|file.json>`; all but `-List` need an elevated shell; preset wildcards read what is on the PC; a preset Run goes through `Start-AkariPhases`, so a preset with Phases restarts between them), then elevation (the elevated console stays visible: launch banner, live log), Core and tweak loading, and dot-sourcing `UI/*.ps1`; after the window closes for One-click, the AkariOS preset's Run in the console (`New-AkariPresetRun`, `Start-AkariPhases`).
- `Core/` (dot-sourced function files, no tweak logic):
  - `Log.ps1`: `Write-AkariBanner` (the console banner: the logo in `Assets/ascii.txt` through `Get-AkariBannerArt`, dots white, `+` / `=` dark grey; the old text banner if the file is missing), `Write-Log` (GUI queue, printed to Akari's console window, or straight to the console), `Write-ErrLog` (`%LOCALAPPDATA%\Akari\akari.log`), `Write-AkariProblems <problems> <show>` (the loader's Problems: Warnings to akari.log only, Errors through `<show>` too), `Write-AkariCrash <error> [-Wait]` (`Akari.ps1`'s trap, which covers every branch: akari.log, then a message box when WPF is loaded, else the console; `-Wait` for the RunOnce consoles).
  - `Compat.ps1`: no-op / dialog shims for legacy tweak bodies (`Write-Host`, `Pause`, `Read-Host`, file pickers). Loaded only in the GUI job.
  - `Trusted.ps1`: `Run-Trusted`; `Invoke-AkariRegistryTrusted <rows> <Mode>` (HKLM registry rows written as TrustedInstaller, a few per `Run-Trusted` call; for keys an admin can't change, e.g. Defender's).
  - `Registry.ps1` (literal paths everywhere: `HKLM:\SOFTWARE\Classes\*` is the "all files" key, never a wildcard; a key's unnamed value is Name `'(default)'`; a DWord written as a hex literal compares unsigned): `Set-Reg`, `Remove-Reg`, `Get-AkariRegValue`, `Resolve-AkariRegPath` (HKCU → real user's `HKEY_USERS\<sid>`), `Invoke-AkariRegistry`, `Get-AkariRegistryState` (rows: values, `Binary` = `[byte[]]`, or key rows with no `Name`: `Value` / `Default` = `'Key'` (exists, created empty) or `$null` (deleted with its contents), `Test-AkariKeyRow`, `Get-AkariRegKey`), `Get-AkariUserFolder <name>` (the real user's `AppData`, `Local AppData`, `Desktop`, `Programs`…).
  - `Loader.ps1`: `Get-AkariTweaks <TweaksRoot>` → `@{ Tweaks; Groups; Problems; Ported }`, `Import-AkariTweakFile`, `ConvertTo-AkariTweak`. Rules in plan §7. One owner per registry value: `Find-AkariRegistryOwner` rejects a Tweak setting a value (or something inside a key row) another one-file Tweak already owns. `Requires` must be in `$AkariRequirements`. `Get-AkariPorted` reads `Tweaks/Ported.psd1`, `Test-AkariPorted <ported> <all tweaks>` (pure) reports ids that don't exist. The DISM cmdlets are only called through these.

## Rules

1. One tweak per file. If a file passes ~150 lines, split it. Data-list Groups (same-shape Entries) may be one data file (ADR 0002).
2. Every Toggle and Choice has a Revert to the stock Windows Default (ADR 0001). A Tweak is an Action only when no Default exists; the file says why in one line.
3. No tweak logic in `Core/`. Core = helpers, loader, runner only.
4. The GUI never hard-codes tweaks; it builds from the loader output.
5. Open only the tweak file(s) being changed; don't read the whole `Tweaks/` tree or a bundled `Akari.ps1`.
6. HKCU changes must target the real logged-in user hive, not the elevated/SYSTEM one.
7. Tweak script blocks must not be interactive: no `Pause`, `Read-Host`, `Clear-Host`.
8. Credit upstream sources in `CREDITS.md` when porting a tweak.
9. Never copy code from Winhance (PolyForm Shield). Ideas and layout only.
10. Update this file in the same change whenever the layout or a Core API changes.
11. `_ref/` is reference only: read a file there only when the task names it; never scan it whole, never commit or bundle it.
12. Never launch the GUI or run the CLI on the developer's real machine, in tests or by hand. Tests use fixture tweaks, `HKCU:\Software\AkariTest\<guid>` and `TestDrive:`; CLI tests use `-List` or fake ids. The user does all real testing on a VM — never on the developer's machine. System-changing native commands (`bcdedit`, `shutdown`, …) are called only through a PowerShell function (e.g. `Invoke-AkariBcdEdit`) and tests mock that function, asserting the mock was hit: Pester 3 does not reliably mock a native command (a `Mock cmd` let the real `bcdedit` run once).
